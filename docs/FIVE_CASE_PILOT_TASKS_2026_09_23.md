# Pilot tasks for the five-case review release

Status: operator-ready assessment set, not enrolled customers. Use together with the existing pilot operator packet, consent record and private participant schema. No contacts, invitations, consent, research time or payments are invented in this document.

## Proposed initial users and task

Recruit3–5 actual investment-attraction/economic-development analysts through a specific operator-approved contact list. Explain what data is stored before obtaining consent. Do not record names, emails or contact notes in the public repository. Keep the private participant identifier distinct from a browser-local reviewer label.

Assign one bounded task: decide whether a company/project is worth investigating now, identify the correct Canadian activity/operator, state what the evidence does not show, and record the next action. Include unsuitable/historical cases as well as promising ones. Do not tell users that all five are leads.

|Case|Critical distinction to test|
|---|---|
|Adyen|Membership versus first entry or a documented expansion requirement|
|Cellcentric|Company-wide supplier inquiry versus site-specific demand|
|Roquette|Portage plant versus Winnipeg R&D collaboration|
|Sanofi|Inauguration/operational facility versus actual vaccine production|
|Nature Energy|Foreign-partner withdrawal versus project cancellation|

## Procedure and measures

For each consented participant, counterbalance manual-research-first versus tool-first tasks using the existing task IDs/schema. Manually time active research; page elapsed time includes idle time and is not time saved. Record unknown or incorrect identity judgments rather than forcing positive answers. Capture whether evidence was new, useful and acted upon, the actual proposed action, and how often a wrong company/project inference occurred. Record explicit payment feedback independently from general enthusiasm and from a verified payment record.

The case briefs and worklists can support these tasks now. Browser-local notes must be exported by the user/operator; there is no shared workspace or automatic transmission. Do not email or collect external records without the authorized recipient/data context.

## Acceptance and next decision

A pilot is run only when independent consented users complete actual tasks and their private records pass `scripts/analyse_pilot.py`. A shipped protocol or empty template is not a user trial. Review whether this buyer/workflow receives useful new evidence, whether the site/project distinctions prevent errors, and whether the action path is clear enough to justify continued investment. Do not publish prediction weights or numeric market-fit scores from this small workflow pilot.
